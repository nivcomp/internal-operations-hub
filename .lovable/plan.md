# קביעת סיסמה למשתמש על ידי מנהל

סיסמאות קיימות לא ניתנות לשליפה (הן מוצפנות חד־כיוונית). לכן במקום "להציג סיסמה", נוסיף למנהל אפשרות **לקבוע סיסמה חדשה** למשתמש ולהעביר לו אותה.

## מה ייבנה

1. **כפתור "קביעת סיסמה" בכל שורת משתמש** במסך ניהול הגישה (Access Management).
2. **חלונית קטנה** שבה אפשר:
   - להקליד סיסמה ידנית, או
   - ללחוץ "צור סיסמה חזקה" ולקבל סיסמה אקראית.
3. אחרי השמירה — הסיסמה מוצגת פעם אחת עם כפתור "העתק" ותבנית וואטסאפ מוכנה לשליחה (מייל + סיסמה + לינק לאפליקציה).
4. הפעולה מותרת **רק למנהל סוכנות פעיל**, ונרשמת ביומן הביקורת של הגישה.

## הערות חשובות

- הסיסמה מוצגת רק ברגע הקביעה; אחרי רענון היא לא תהיה זמינה שוב — צריך לקבוע מחדש.
- מומלץ לומר למשתמשת להחליף סיסמה אחרי הכניסה הראשונה.

## פרטים טכניים

- הרחבת פונקציית הקצה `access-admin` בפעולה חדשה `setUserPassword`:
  - אימות JWT + בדיקה שהקורא הוא `agency_admin` פעיל (אותה שמירה קיימת ב־`requireAdmin`).
  - ולידציה: סיסמה באורך 10+ תווים; המשתמש חייב להיות קיים ב־`profiles`.
  - עדכון דרך `admin.auth.admin.updateUserById(userId, { password, email_confirm: true })` עם מפתח service-role בצד שרת בלבד.
  - החזרת `{ ok: true }` בלבד — הסיסמה לא נשמרת בשום טבלה ולא נרשמת בלוגים.
- `src/services/accessApi.ts`: פונקציה `setUserPassword(userId, password)`.
- `src/pages/AccessManagementPage.tsx`: כפתור + חלונית עם יצירת סיסמה אקראית (crypto), הצגה חד־פעמית, העתקה ותבנית וואטסאפ.
- סגנונות קטנים ב־`src/styles.css` בהתאם לרכיבים הקיימים.
- אימות: `pnpm run build`, ואז קביעת סיסמה לחשבון הבדיקה וכניסה מוצלחת איתה.
